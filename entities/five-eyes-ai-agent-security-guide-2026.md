# 五眼联盟 AI Agent 安全指南（2026）

## 基本信息

| 项目 | 内容 |
|------|------|
| 原文标题 | Careful Adoption of Agentic AI Services |
| 中文标题 | 《审慎部署智能体AI服务》 |
| 发布日期 | 2026年5月1日 |
| 参与机构 | 澳大利亚信号局（ASD/ACSC）、美国（CISA/NSA）、加拿大（CCCS）、新西兰（NCSC-NZ）、英国（NCSC-UK） |
| 中国译者 | 公安部第三研究所网络安全法律研究中心 + 西安交大苏州信息安全法学所 |

## 核心建议（编写机构立场）

1. **将自主智能体 AI 风险与缓解策略与组织现有安全模型及风险态势对齐**
2. **采用自主智能体 AI 时优先考虑安全，评估其用途**
3. **绝不授予其广泛或无限制的访问权限**，尤其禁止访问敏感数据或关键系统
4. **仅将自主智能体 AI 用于低风险、非敏感任务**

## 四大安全风险类别

### 1. 权限风险
- 权限失陷、权限范围蔓延
- 身份仿冒、智能体冒充（"混淆助理模式"）
- 示例：采购智能体被攻陷后修改合同、批准付款

### 2. 行为风险
- 目标错位：智能体找到违背初衷的捷径
- 欺骗行为：智能体歪曲行动以避免被关闭
- 涌现能力：复杂模型展现开发者未预见的行为

### 3. 结构风险
- 编排与资源：拒绝服务、资源耗尽攻击
- 第三方组件：工具/智能体"抢注"
- 恶意智能体在多智能体系统中引发级联失效

### 4. 责任风险
- 动作与流程不透明，难以追溯
- LLM 幻觉导致准确性风险
- 可见性不足，恶意行为未被及时发现

## 安全最佳实践（四阶段）

### 设计阶段
- 受控上下文：用清晰指令层次结构组织提示词
- 监督机制：设置人类控制点，支持"人在回路"
- 身份管理：每个智能体独立主体，密码学锚定身份（mTLS 认证）
- 纵深防御：多层重叠安全控制

### 开发阶段
- 红队演练：识别潜在漏洞与非预期行为
- 弹性设计：嵌入故障安全默认值与遏制机制
- 输入管理：提示词注入过滤器与语义分析

### 部署阶段
- 威胁建模：与现有安全框架对齐（零信任、NIST）
- 渐进部署：分阶段逐步提升访问权限与自主性
- 默认安全：不确定场景下智能体停止并升级给人类

### 运行阶段
- 持续监控与审计：监控所有智能体运行，而非仅输入输出
- 输出验证：多源验证关键方面准确性
- 人在回路：高影响动作必须人类审批
- 权限管理：持续严格权限管理，细粒度控制
